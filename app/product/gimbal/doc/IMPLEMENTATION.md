# Gimbal 软件实现说明

## 1. 目录和依赖

`component/gimbal` 是产品无关层，只依赖值类型、HAL 抽象和 OSAL 原子语义；
不包含板级通道号、GPIO 或厂商 SDK。`app/product/gimbal` 负责设备树映射、
参数实例、任务频率和产品状态编排。

数据流如下：

```text
TIMER6 16 kHz ISR -> SPI DMA async -> IMU RX-DMA ISR
                                      -> SensorBatchCore ping-pong buffer
                                      -> g_closed (16 samples / 1 kHz batch)
                                         -> EKF + Hall + kinematics
                                         -> dynamics + 2DOF controller
                                         -> safety gate -> voltage FOC -> PWM
planner -> typed snapshot --------------------^
IMU temperature -> thermal controller -> heater PWM
```

`SensorBatchCore` 是设备无关编排器。每个异步源只提供 prepare/start/stop 三个
函数，核心不包含 IMU 寄存器、SPI 控制器或产品业务。定时器 ISR 只计算逻辑
时间戳、选择当前 frame 并启动非阻塞传输；正常完成回调固定发生在 RX-DMA ISR。
DMA ISR 只封存 frame、切换 ping-pong 状态，并在凑满 16 点时用 ISR-safe API
唤醒 `g_closed`。寄存器解码、浮点换算、EKF 和控制均在任务上下文执行。

两个静态缓冲区使用 `Free -> Filling -> Ready -> Reading -> Free` 所有权状态。
DMA 永不写入 `Ready/Reading` 缓冲区，闭环回调收到的 const 指针只在本次回调
期间有效。若任务尚未释放上一批，核心丢弃新批次、增加 overrun 计数并触发
关断链，绝不覆盖消费者正在使用的数据。采样频率必须是闭环频率的整数倍；
当前 `16000 / 1000 = 16`，错误配置会在编译期或启动期被拒绝。

逻辑采样时间戳按配置频率用整数商和余数累加，因此 16 kHz 下会以
62/63 us 步进且长期无累计漂移。该时间戳表达期望采样时刻，不代表实测 ISR
到达时间；IRQ 抖动和触发到 DMA 完成的延迟必须在目标板上用逻辑分析仪验收。

每个共享主题仍只有一个发布者。批次内的 IMU 原始数据通过指针零拷贝传给
闭环任务；对其他任务公开的最新 IMU、姿态、关节、命令和安全状态使用三缓冲
快照，读者不持有算法对象，也不直接读写别的任务内部状态。
EKF 状态为三轴姿态误差与三轴陀螺零偏，传播完整 6×6 协方差，并以 Joseph
形式更新。静止零偏学习同时要求关节速度、校正后陀螺幅值和重力模长通过门限，
避免手柄整体运动时把真实角速度吸收到零偏中；无磁力计条件下绝对 yaw 仍不可观。
陀螺和加速度分别使用工厂 3×3 组合校正矩阵，将比例、轴不正交和 IMU 到相机
外参一次映射到相机坐标系；加速度零偏及陀螺恒温零偏/温度斜率独立保存。
估计器按批次内 16 个 IMU 样本逐点传播，不丢掉中间角增量；输出在允许的
短时窗口内外推到控制读取时刻，超过窗口则发布 Invalid，而不是继续使用陈旧姿态。
Hall 速度同样使用相邻实际捕获时间计算。控制任务在计算 Jacobian 和命令前再次
检查关节、姿态和规划参考的新鲜度，因此不必等待 100 Hz supervisor 才能撤销
陈旧输入对应的功率输出。

## 2. 任务模型

| 任务 | 默认频率 | 职责 |
|---|---:|---|
| TIMER6 ISR | 16000 Hz | 同时触发已注册异步传感器，不做算法 |
| SPI RX-DMA ISR | 16000 Hz | 封存 IMU frame、切换批次并按需唤醒任务 |
| `g_closed` | 1000 Hz | 16 点 EKF、Hall、运动学、前馈反馈和 PWM 唯一写入 |
| `g_planner` | 200 Hz | SO(3) 平滑梯形参考和跟随手感 |
| `g_thermal` | 20 Hz | IMU 恒温、升温诊断和高环境温度降级 |
| `g_supervisor` | 100 Hz | 超时、限位、奇异、堵转和可选采样保护 |

主线程、闭环任务和三个慢速任务分别向 `system_watchdog` 报送心跳。健康监控是唯一的
FWDGT 喂狗者；任一关键任务超过窗口未运行时，健康监控进入 fatal 路径并停止
喂狗，由独立 40 kHz 时钟域完成硬件复位。电机外部 disarm 请求另有原子门控，
最迟在下一个 1 kHz 控制周期撤销输出，不依赖 100 Hz supervisor 才生效。

所有任务栈由产品静态提供。安全任务只发布授权，只有 `g_closed` 可以 arm、
disarm 或更新三相占空比，避免多个任务竞争功率级。
三相占空比通过 PWM HAL 的单次批量接口写入三个预装载寄存器；写入期间禁止
影子更新，使同一 PWM 周期不会混入两组命令。重新 arm 时先强制装载中性占空比，
再开放通道输出，避免暴露上次 disarm 前的活动比较值。
安全主题即使因并发读者占槽而暂时发布失败，也不是唯一关断链：陈旧输入、
控制/映射/驱动失败和 supervisor 故障都会直接清除原子电机请求，控制任务在
下一个 1 kHz 周期关闭三轴输出。安全管理器首次锁存时还保存故障位、时间、
关节角/速度、IMU 温度、q 轴命令和母线值，后续连锁故障不会覆盖根因现场。
该首故障快照当前保存在 RAM 并输出到诊断日志；量产持久化应由独立故障日志
组件异步完成，不能在 1 kHz 控制路径直接擦写 Flash。
产品将 FreeRTOS 动态堆限制为 8 KiB；四个产品任务、主任务、健康监控任务和
内核任务均使用静态栈。五秒诊断同时输出各任务栈最低剩余量、周期失约计数和
堆历史最低剩余量，量产配置必须依据压力测试结果保留安全裕量，不能只按链接
成功缩减。
主任务栈固定为 6 KiB，用于覆盖启动阶段 NVS 工厂记录选择和写后读回的嵌套
对象；该预算仍须通过目标编译器 stack-usage 报告及最坏路径高水位实测确认。
Active 状态下任一任务失约、SPI 源错误、触发忙、批次未释放或派发失败都会
锁存 `DeadlineMissed`；`g_closed` 在看到计数变化时先通过原子门控撤销电机
请求并立即 disarm，之后
才由 supervisor 固化故障上下文。待机和加热阶段只更新失约基线，不把启动抖动
带入下一次 arm。

## 3. 启动和失效安全

启动顺序为设备自动初始化、NVS 挂载、参数选择、算法配置、加热器安全启动、
规划/热控任务、传感器流水线、首批闭环处理、安全监督和镜像确认。首批等待
最多 20 ms；正常情况下 1 ms 内完成。超时不会跳过监督，监督仍会启动并把真实
Hall/IMU/EKF 故障带入安全状态，避免空主题造成竞态误报，也避免故障被隐藏。
工厂记录缺失、CRC 错误、schema 不匹配或 capability 与
当前固件不一致时进入 `Calibration`，电机授权恒为 false。

工厂和用户参数各保留 A/B 两个 NVS ID，以 32 位代际号选择最新有效记录。
两类记录使用互不重叠的 NVS 日志区，使任一区域在 GC 时的两个活跃副本均能
装入一个 2 KiB 擦除页；挂载时还会按实际写块和记录大小重新核算容量。
记录先由 NVS 完成掉电安全提交，payload 内部再校验 magic、schema、长度、
CRC32 和 commit marker。写入返回后立即从目标 A/B 槽读回并复核代际和 CRC，
只有读回成功才更新 RAM 中的当前代际。
PWM 通道、周期等板级拓扑只来自 DTS，不再复制进可变工厂参数；工厂记录仅保存
每轴电压 FOC 数值标定和硬件版本。编译期及 NVS 挂载前都会核算两份工厂记录和
两份用户记录能否同时装入一个擦除扇区，防止参数扩展后在现场 GC 时才暴露容量
不足。当前工厂 schema 为 5，旧布局不会被静默解释。工厂参数还分别限制用户
可配置的跟随死区和跟随增益；更新工厂记录后，现有用户记录立即失效，必须按
新安全包络重新验证和提交。

每轴反馈链按 `notch -> lead -> low-pass -> PI` 执行，动力学输出作为独立
前馈支路在限幅前叠加。notch、lead 零极点、低通截止频率、采样频率和增益均
属于工厂参数；运行时要求参数采样频率与 Kconfig 控制频率一致。Follow 模式
锁定 roll 并跟随相对手柄 pitch/yaw，FPV 跟随三轴相对转动，Lock 捕获进入
模式时的相机姿态，Recenter 规划回世界中性姿态；模式切换会重新捕获手柄和
相机原点，防止使用绝对姿态造成目标跳变。

控制周期按当前 Hall 机械角实时计算 `R_HC(q)` 和 `J(q)`。相机坐标反馈通过
`J(q)^T R_HC(q)` 分配到三个关节，参考角加速度通过
`J(q)^-1 R_HC(q)` 转换为关节加速度后进入惯量前馈。映射非有限或 Jacobian
低于工厂门限时，该周期命令直接标记 Fault，控制任务撤销全部电机输出。

## 4. 当前硬件接入边界

参考板尚未绑定可选相电流、母线电压、驱动温度和 MOS 温度的板级采样适配器。
若构建时打开这些 Kconfig 项或选择电流 FOC，CMake 会直接拒绝构建；运行时
安全层仍会对 capability 与反馈有效性做第二道校验。只有补齐对应 DTS、同步
采样、驱动读取和故障注入验证后，才允许移除构建门禁并发布 Valid 反馈。

参考板继承 GD32F503 demo 的时钟、串口、SPI 和 IMU 定义，并增加三组双 Hall
ADC 通道、三组 3PWM 定时器和一个加热 PWM。参考文件没有猜测电机 PWM 引脚、
功率级 enable/brake/fault 引脚；实际产品必须依据原理图补充 pinctrl 和硬件
关断链，然后执行 `VALIDATION.md` 中的带电门禁。
电机子设备只实例化而不在 initcall 阶段自动启动；产品在完成 NVS 选择、硬件
版本和 capability 校验后才配置电机对象。无有效工厂参数时只使用受限的标定
参数建立软件对象，功率输出授权仍固定为 false。
每路 Hall 通道在设备树中显式配置 ADC 采样保持时间；参考值为 128 个 ADC
周期，最终值须按 Hall 输出阻抗、RC 滤波和 ADC 输入模型计算并用示波器验证。
当前 Hall ADC 驱动没有外部触发 DMA，因此三轴 Hall 在每个 1 kHz IMU 批次
边界由 `g_closed` 顺序读取。这提供确定的软件相位关系，但不是三轴 ADC 与 IMU
的同一硬件边沿采样。若机构带宽或 Hall 速度估计对这段偏差敏感，必须增加
定时器 TRGO + ADC scan DMA 适配器，再作为 `SensorBatchCore` 的第二异步源接入。

SPI0 以 10 MHz 读取 15 字节帧，理想线上时间约 12 us，小于 62.5 us 采样周期；
真实 CS 建立/保持时间、DMA 中断延迟和最坏抢占仍须在目标板测量。TIMER6、
DMA0 channel 3/4 当前使用相同 RTOS-safe 中断优先级，ISR 不执行浮点、日志、
锁或内存分配。GD32F503 没有数据 Cache；移植到带 D-Cache MCU 时，DMA buffer
必须放入 non-cache 区或在所有权切换处执行正确的 clean/invalidate。

基础版本是 Hall 有感电压 FOC。没有相电流时，命令单位是伏特近似量，不是
真实转矩；没有母线采样时使用工厂标称电压；不存在的温度或电压采样不得在
工厂 capability 中置位。`maximum_modulation` 定义为 SVPWM 线性电压矢量
半径的比例，电压限制为 `Vbus / sqrt(3)` 的相应比例；非有限命令会先关闭
PWM 输出，不能依靠最终占空比钳位掩盖上游错误。
加热 PWM 写入失败同样会锁存驱动故障、关闭并停止加热输出；后续周期持续发布
Fault，必须重启并完成硬件诊断后才能恢复。

## 5. 时钟与 PWM 一致性

GD32F503 公共启动代码按 8 MHz HXTAL、预分频 2、PLL0 倍频 50 配置
200 MHz 系统时钟，并按 `/4 -> /2 -> /1` 分级切换 AHB。APB1 为
100 MHz，但定时器时钟倍频后仍为 200 MHz；APB2 和其定时器均为
200 MHz。外部晶振或 PLL 未在有限窗口内稳定时，启动代码关中断并停机，
不会继续启动 RTOS 或功率级。

三轴中心对齐 PWM 使用 `PSC=0, ARR=4999`，目标频率 20 kHz；加热器使用
`PSC=199, ARR=999`，目标频率 1 kHz；传感器触发 TIMER6 使用
`PSC=0, ARR=12499`，由 200 MHz 定时器时钟产生精确 16 kHz。板级代码编译期
断言 TIMER6 频率与 `CONFIG_GIMBAL_SENSOR_HZ` 一致。设备树生成代码还断言电机节点
和被引用定时器的周期一致，U/V/W 通道唯一性也在生成代码中断言；加载工厂
参数时核对硬件版本。周期和通道不属于工厂记录，任何参数更新都不能改变板级
PWM 拓扑。

时钟切换序列和寄存器位域约定来自 [GD32F50x 官方固件库]。量产板仍须用
MCO/示波器分别确认系统时钟、20 kHz 三相 PWM 和 1 kHz 加热 PWM。

## 6. 实现与整机交付边界

当前仓库已实现算法、固定容量共享内存、任务编排、参数掉电安全、安全状态机和
电压 FOC 软件链。Hall 零位/电角标定提供可复用计算器，但低电压对齐动作、工装
通信和参数签核由生产工装编排；频域控制已提供 notch、lead、低通和 PI 结构，
扫频激励、FRF 拟合及裕度报告必须在真实机构或 HIL 上完成。

参考 DTS 尚未获得实际 PCB 的 PWM pinctrl、功率级 enable/brake/fault 和 Hall
模拟引脚，因此本轮构建与主机测试不是带电验收。可选相电流、母线电压、驱动
温度和 MOS 温度也保持构建期关闭；补齐这些硬件适配前，禁止移除对应门禁。

[GD32F50x 官方固件库]: https://github.com/GD32-MCU-IOT/GD32_FreeRTOS
