# 配置、构建产物与验证证据

修改 SDK、驱动、构建配置或导入上游代码时阅读。目标是证明修改进入了正确产物，
并明确哪些行为仍需板上验证。

## 发现实际构建上下文

从仓库说明、CI、构建脚本、CMakePresets、CMakeCache、compile_commands 和生成配置，
定位应用、板型/SoC、工具链、构建目录和产物。不要猜 `out/`、`build/` 或 ELF 名称。
例如 Lark 的 `<build_dir>/lark/lark.elf` 只是当前构建目标确认后可用的布局。
多个 ELF 时，核对 target、配置、链接脚本和构建日志；时间最新不能单独决定烧哪个文件。

记录源码 revision/脏改动、实际命令、编译器版本和配置。Windows 沿用项目已验证的
PowerShell、Git Bash 或 WSL 入口，避免换 shell 导致工具链和路径语义变化。
跨 Windows/WSL 的路径以各自进程看到的文件为准，必要时比较文件哈希。
在清理之前保留已有产物与日志；需要干净构建时优先另建输出目录，不默认删除用户的 `out`。

## 验证改动确实参与构建

沿实际链路检查，不凭文件在目录里就认为功能已启用：

```text
板级配置/overlay
  → DTS binding / 生成 DTS
  → Kconfig / 生成 .config
  → CMake 源文件选择
  → 头文件及 syscall/其他代码生成输入
  → 编译和链接
  → ELF / map / 打包镜像
```

- 新驱动：核对配置选项、父目录接线、binding include 和属性默认值。
  使用 syscall 的框架还需检查头文件注册及 wrapper/marshalling 生成，不只增加源文件。
- 接口改动：核对所有实现、调用者、结构体 ABI、枚举/索引表及可选配置。
- DMA/缓存相关：在 map/ELF 中确认缓冲地址、段属性、对齐、RAM 可达性及 VMA/LMA。
  段名拼写错误可能生成 orphan section；编译成功不等于缓冲进入了预期 SRAM。
- 生成工具：把依赖缺失、生成器失败、打包失败计入验证结果，不能因 `.o` 已生成就声称完整构建通过。

可按工具链选择离线命令，并使用实际绝对路径：

```text
<readelf> -h -l -S <firmware.elf>
<objdump> -h <firmware.elf>
<nm> -n <firmware.elf>
```

记录最终 ELF/BIN/HEX/map 的路径、大小、时间和需要关联时的 SHA-256。
检查 app slot、包头大小、向量表、入口和装载地址的关系；不能默认裸 BIN 从 Flash 起始处烧录。

## 按故障机制选择验证

执行项目要求和本次改动相关的构建/测试。核对退出码与完整日志、区分已有警告和本次新增警告。
共享层变更按受影响的配置差异选择代表构建；普通小改不自动要求整个板型矩阵。

回归检查应能辨别修复是否有效，例如：

- 缓冲/队列：耗尽、取消、失败回收、重入提交和跨计数器回绕的长期流量。
- 非 DMA 串口：突发、单字节/短帧尾部、高 ISR 负载、错误后恢复及丢包/错字计数。
- DMA：缓存开关、非对齐长度、缓冲边界、所有权交接和 CPU/外设可见性。
- 状态机：失败/超时后退出条件、重试上限、资源释放与重新进入。

测试规模随实际机制和项目契约确定，不把某次历史字节数、速率或缓冲数量当通用阈值。
源码断言或单次 smoke 不能替代吞吐、时序、压力和电气验证。

## 分层报告

| 层次 | 可以证明 | 不能替代 |
|---|---|---|
| 源码/主机测试 | 调用链、纯逻辑、资源与协议契约 | 外设寄存器行为、真实中断时序 |
| 目标构建/产物检查 | 指定配置编译链接、段布局、生成和打包 | 板子烧入该产物或运行正确 |
| 烧录回读校验 | 所核验地址/长度的目标字节匹配 | 功能、实时性与电气行为 |
| 板上验证 | 给定板型、负载、固件和时段的观察结果 | 未测配置或更长运行时段 |

报告已执行命令、结果和未覆盖项；无法运行时说清缺失依赖，不编造 PASS。
需要连接真实 MCU 时，使用可用的 `$mcu-ai-debug`；未安装时遵循同样边界：
保留已有调试器 owner，先确认目标与现有授权，再执行会改变运行状态的操作。
